Optimised: 6 steps -> 3, 2 CI round trips -> 1; cut: installing tofu plus a state backend read on the drill job (credentials a drill never needed) -- the sibling secrets' own metadata already names the vault and key.

Verify: `python3 -m pytest -q tests/test_incident_crew722_seed_needs_no_tofu.py`

## Options considered
- Install opentofu on the rotation-drill job and init the state backend: adds state-backend credentials to a job that only writes one canary secret, and every other tofu-less caller of idp-cloud stays broken. Rejected.

- Chosen: resolve from the compartment's own ACTIVE secrets -- no new credentials, no state read, correct on every machine oci works on, and a BLIND that keeps the drill red when nothing can be resolved.
