## What

The founder's rule from `docs/reference/incidents/2026-08-30-three-incidents-one-defect.md`, where he
listed it under *"Named here so it is not mistaken for done ... Not built"*: **every infra change ships a
control or says why not.** He asked for it machine-checked on the pull request rather than written in a
rules file — *"prose in a CLAUDE.md is itself an invariant living in someone's head, you'd be violating
your own pattern"*. A law nobody can be stopped by is a wish (LAW 44).

`policy/operating_model.rego` gains `control_shipped`. A pull request touching `platform/`, `clusters/`
or `bin/idp-*` carries `Control: <path>` naming a file **that pull request changes** under `tests/`,
`policy/` or `platform/edge/`, or `Control: none: <reason>`.

Optimised: 9 steps -> 4, 5 round trips -> 2; cut: discovering broken fixtures one failing test run at a
time — every test is swept for a clean-assertion up front and all three are patched in one pass.

Cost-delta-usd-month: 0
Control: tests/test_incident_2026_08_30_every_infra_change_ships_a_control.py

## Three prefixes, not a fourth definition

The rule grades the same `platform/`, `clusters/`, `bin/idp-*` that `verify-claims.yml` already calls
touching the world. A test pins the two together so they cannot drift apart (LAW 23).

## Options considered

**1. Infer the control from the diff, no body line at all.** Measured first, because it costs real work
nothing: 5 of the 5 most recent infra pull requests already change a file under `tests/`. Rejected on
evidence — #1027, the pull request this incident is named for, *also* changed three test files and would
have sailed straight through. A rule that waves through the incident it is named for is not a rule.

**2. Require the explicit line (taken).** The author must point at a control and, in pointing, notice when
there is nothing to point at. Costs one line on infra pull requests, the same shape as the `Drill:`,
`Verify:` and `Optimised:` lines the estate already demands.

## What this does not claim

Naming a control file is **not** proof the control covers the change. It does not, the rule's own comment
says so, and the test says so. Claiming otherwise would be this estate's fix-proved-on-the-wrong-surface
class. What is proved is that a world-touching pull request cannot reach a merge without either pointing
at a control it ships or writing down why there is none.

## Proof the control works, on the real pre-fix state

A control is not proved by a fixture invented to suit it. `policy/fixtures/opmodel-no-control.json` is the
shape of the real #1027: `clusters/oke/platform.yaml`, three `platform/` manifests, three test files, and a
body naming no control for the nine-row automatic-uninstall sweep — the change that destroyed the evidence
of the next incident and that the founder ordered undone in #1032.

## Nobody in flight is refused

Same grandfather clause as `optimised_plan` and `self_heal_has_breaker`: a pull request opened before
`2026-08-31T04:00:00Z` is never refused for a line nobody could have known to write (LAW 38). Blast radius
on open work is zero, and a test proves both sides of that boundary.

## The sweep is a test now

Four fixtures other suites assert exit 0 on were refused by this rule, and each was found by a red CI
run rather than by the sweep meant to close it — twice because the sweep graded the wrong conftest
namespace and so measured nothing, twice because it globbed `tests/*.py`, which does not match a
subdirectory, and the last two live in `sovereign/tests/bdd/`. Both are the silent-green class this
PR's own second commit fixes, in my own sweep.

The sweep is therefore no longer something a session performs: `test_no_other_fixture_in_the_tree_is_refused_by_this_rule`
asserts every `opmodel-*.json` except the two this rule owns is clean of `rule=control_shipped`.
Watched failing with one `Control:` line removed, clean with it back (LAW 45).
