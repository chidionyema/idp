## What

The operating-model gate refused idp#1014 with `Drill: otto-parity names no entry in
drills/catalogue.yaml` while the branch it was judging carried that exact row. `bin/pr-report`
fetched the pull request's own head catalogue **only when the pull request's own diff touched
`drills/catalogue.yaml`**. idp#1014 was stacked on edcf54d4 (#1013), which added the row, so its
own diff did not touch the file, the gate fell back to main at f92233e4, and correct work was
refused (LAW 38, run 33330388899).

`bin/idp-pr-catalogues` now resolves both copies — main's and the head's — unconditionally, and
`bin/pr-report` calls it. A head copy that cannot be fetched is skipped and named on stderr, so
losing the network degrades the gate to main's catalogue rather than crashing it.

Optimised: 6 steps -> 3, 2 round trips -> 2; cut: the `jq -e '.files | index(...)'` branch — the
condition it guarded was the defect, so removing the input is cheaper than testing it, and the
head fetch it was saving happens on every gate run anyway when the file *is* touched.

Cost-delta-usd-month: 0
Control: tests/test_incident_idp1014_gate_reads_head_catalogue_always.py

## Remove the bad input, do not guard it

The old code asked "does this diff touch the catalogue?" and used the answer to decide whether the
head copy was worth fetching. That question is not a proxy for "does the head carry the row" — a
stacked branch, a merge from a sibling, or a rebase all break it, and two of those have now broken
it in production. The condition is deleted rather than corrected: the head catalogue is always
resolved, and `bin/idp-drill-names` already treats a missing file as contributing nothing.

## Options considered

**1. Widen the condition — also fetch the head copy when any ancestor commit touched the
catalogue.** Rejected: it keeps a predicate whose failure mode is silent (the gate still answers,
just against the wrong file), and it needs the merge-base plus a second diff, so it costs a round
trip to be wrong in a narrower set of cases.

**2. Fetch the head copy unconditionally (taken).** One `gh api` call the gate run was already
willing to make, no predicate to be wrong about, and the failure path is explicit on stderr
instead of a quiet fallback. LAW 23, the smaller road.

## What this does not claim

This does not make the gate read every ancestor's catalogue, and it does not merge the two copies
by row semantics — `bin/idp-drill-names` takes the union of names, first occurrence winning. A row
renamed on the head and still present on main is therefore accepted under either name. That is the
same behaviour the rule had before idp#191, and it is not what either incident was about.

## Proof the control works, on the real pre-fix shape

`test_incident_stacked_pr_resolves_the_head_catalogue_though_its_diff_does_not_touch_it` builds
idp#1014's exact shape: a fake `gh` whose PR diff does **not** list `drills/catalogue.yaml` while
the head ref serves a catalogue holding `otto-parity`. Against the pre-fix `bin/pr-report` the row
is absent and the gate refuses; against `bin/idp-pr-catalogues` both paths are printed and the
name resolves.

`test_unfetchable_head_catalogue_degrades_to_main_and_is_named` proves the other side: when the
head fetch fails, exit is 0, main's path is still printed, and the reason is on stderr — never a
crash, never a silent BLIND.
