## What

Blueprint 2 from the founder's 2026-08-30 incident report, listed there under *"Named here so it is not
mistaken for done ... designed, not built"*: **kubeconform type-checks every rendered manifest before
merge.**

## The first cut had no caller

Worth saying plainly, because it is the reason four of the six tests exist. The script and the incident
fixture were written first and wired to nothing: no CI job ran either, so the ongoing coverage was rung 5
(documented) = zero, and the two tests that existed graded a fixture rather than a gate. Two of the tests
added here grade the wiring itself — that rung 9 keeps its render, that rung 9c judges it, that exactly
one render is kept, that CI installs the binary. All four fail against `origin/main`, checked.

## Options considered

**1. A separate CI step running `bin/idp-kubeconform` over the platform tree.** The obvious wiring, and
what the script was built for. Rejected on measurement: it renders the same dirs a second time.
crew#584 measured that render at 160 s of a 422 s job, and this would have restored the whole of it for
a check that itself costs under a second.

**2. Hand over rung 9's render (taken).** `IDP_RENDER_KEEP` copies `kz-*.yaml` and `*.final.yaml` out
before the render's own trap deletes them. Kyverno judges policy on those bytes, kubeconform judges type
on the same bytes. `plain-*.yaml` is deliberately not handed over: it is a filtered subset plus synthetic
Pod stand-ins built so Kyverno sees what a controller would create — real for a policy verdict, not a
real object to type-check twice.

## What this does not claim

**This rung would not have refused idp#1027 on the live tree, and the docstring says so where a reader
meets it.** Flux substitutes `${vars}` in the *cluster*, after everything CI renders. In a render,
`appID: ${githubAppIDQuoted}` is the literal string `"${githubAppIDQuoted}"` — a string, so it
type-checks clean either way, pre-fix and post-fix alike. What refuses that exact shape is the permanent
fixture, which holds the post-substitution bytes.

Saying this is the point rather than a caveat: a control named for an incident it cannot catch on the
live tree is this estate's third defect class (fix-proved-on-the-wrong-surface, 3 on the ledger). The
live rung's real coverage is every **other** type error in every rendered manifest — a field typed int
where its schema says string, a misspelled enum, a map where a list belongs — a class nothing here
graded before. Closing the substitution gap needs a stand-in value per substituted key and is a separate
control, not this change.

## Schemas, and the one that is skipped

Built-in Kubernetes kinds come from kubeconform's `default` location, pinned to 1.34.11 — the newest
minor `yannh/kubernetes-json-schema` publishes; the OKE cluster is on v1.35.2, and
`IDP_KUBECONFORM_K8S_VERSION` overrides, because the cluster's version and the schema registry's
coverage move on two different clocks. The eleven CRDs this estate ships against (Flux,
external-secrets, Kyverno, Tailscale) are vendored, not fetched live, so the idp#1027 regression can
never go BLIND because a catalog CDN blinked. SPIRE publishes no schema in `datreeio/CRDs-catalog`; its
resources fall through `-ignore-missing-schemas` and are counted and printed as `skipped` in the same
line as everything judged — never silently passed (LAW 28). That is the `skipped=1` above.

## It found a real one on its first run against the live tree

The rung is not a fixture exercise. Its first offline-gate run over the whole platform tree
returned `valid=708 invalid=4 errors=0 skipped=145`, and the four are real:

```
FAIL  langfuse.final.yaml: Deployment langfuse-web    (apps/v1): at '/spec/template/spec/containers/0/env/45/value': got number, want null or string
FAIL  langfuse.final.yaml: Deployment langfuse-worker (apps/v1): at '/spec/template/spec/containers/0/env/45/value': got number, want null or string
FAIL  langfuse.final.yaml: Pod        langfuse-web-pod    (v1): at '/spec/containers/0/env/45/value': got number, want null or string
FAIL  langfuse.final.yaml: Pod        langfuse-worker-pod (v1): at '/spec/containers/0/env/45/value': got number, want null or string
```

`LANGFUSE_S3_MEDIA_UPLOAD_MAX_CONTENT_LENGTH` renders as `value: 1e+09` — the langfuse chart
2.0.2 default put through Helm's float marshalling. Unquoted scientific notation is a **number**
to every YAML 1.2 reader, and `core/v1` `EnvVar.value` declares a string. Nothing in this
pipeline had ever said so: kyverno grades whether a Pod is allowed, not whether a field is the
type its schema declares. It is the same class as idp#1027, sitting in the tree unremarked.

Fixed in the release's existing `postRenderers`, restating the key as a string on both
deployments. Re-rendered and re-judged: `34 resources found in 1 file - Valid: 34, Invalid: 0`.
No second guard is added for it — rung 9c *is* the guard, and it catches a chart bump that
re-introduces the number (control ladder: adding a control deletes the weaker one it subsumes).

Worth naming: PyYAML reads `1e+09` as the **string** `'1e+09'` (YAML 1.1 needs the decimal point),
so a Python sweep over the render sees nothing wrong. Only a YAML 1.2 reader — kubeconform's, and
the API server's — sees the number. A hand-rolled Python check for this class would have been a
silent green.
