## Why this is 41 files, over the 40 ceiling
The change IS the sweep. One defect surface appears in 13 manifests and nine HelmRelease rows, and fixing them in 13 pull requests would leave the estate half-swept, where the new admission rule refuses manifests not yet swept. The base is the current origin/main (f3988c2f) and no other session's history rides along: one commit, and every file in it is either a hand-kept list deleted, an automatic uninstall taken back out, the rule that makes both inexpressible, or a test of those. Twenty-two of the 41 are two-line edits.

## Options considered
- Keep the per-workload lists and add a test that every mounted entry appears in its workload's list. Rejected: that is the control that already failed twice. It grades a list against a list, the same shape as the assertion that stayed green through both incidents — a test written from the same manifest it grades cannot see an entry nobody added to either side.
- A CI-only check that greps the manifests. Rejected: it grades git, not the cluster, so a workload applied by any other path (a peer's overlay, a hand kubectl during break-glass) is unseen. The control has to sit where every workload converges, which is admission.
- Chosen: rung 0 plus rung 1. Delete the list from every manifest (`reloader.stakater.com/auto: "true"`, which Reloader resolves against what the pod actually references, so there is no list to keep in step), and make the old shape inexpressible with a Kyverno policy that injects the annotation at admission and denies any workload carrying a hand-kept list.

## Automatic uninstall is taken back out
idp#1027 set `remediation: { strategy: uninstall }` on nine HelmRelease rows. Founder, 2026-08-30: uninstalling a wedged release turns a degraded service into a deleted one — its PVCs, PDBs and mounted state go with it — and it erases what says which invariant was violated, which is the state an incident is converted into a control from.
