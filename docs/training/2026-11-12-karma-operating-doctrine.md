## Fundamental economic and scientific object

An instruction is a **debt issuance only when accepted**: a bounded, typed
obligation with expected externally observable outcome, accountable custody and
recovery owner. Source truth is the existing authorised FLOW acceptance.
Issuer is not debtor. An agent's work may split into child obligations; every
child has a causal parent and accountable custodian. Token spend is ONE axis of
resource use alongside latency, compute, CI runner time, human interruption,
risk, opportunity cost and unavailable observations. Verified utility and
safety cannot be reduced to an arbitrary scalar subtraction from token cost.

A verified proof-of-yield **settles a declared condition**. It is never inferred
from a green branch, schema-valid report, invocation count, model's own verdict
or a timed-out checker. Unknown verification and missing cost are UNKNOWN,
not success/zero. Open obligations remain on the estate until discharged or
explicitly withdrawn by authorised authority with immutable provenance.

## Chronology, causality, identity

Minimum join IDs for an observation: `instruction_id`, parent event IDs,
`agent_urn/session_id`, QUAD signing key identity (when verifiable), exact
model provider, requested/returned model and disclosed version/fingerprint,
config generation, source SHA, evaluator/policy SHA and independent receipt.
Preserve distinct source-claimed event time, trusted observation time,
durable ingestion/commit time, external anchor time and valid/transaction times.
A timestamp is not a cryptographic causal link. Missing links stay visible.

Record projected states `ASSERTED`, `OBSERVED`, `VERIFIED`,
`FALSIFIED`, `MISSING`, `UNLINKED`, `STALE`, `UNKNOWN`.
QUAD's existing append-only hash chain and persisted identity retain authority.
Never call a nonempty signature VERIFIED without checking the public key,
nor call a stored DB anchor externally confirmed without fetching it separately.

## Inherited karma and scientific reward

At verified failure, create or extend a failure-*class* obligation linked to
the original event, applicable law, mistake/impact, source/model lineage and
reproducible counterexample. On model succession or handover, shared memory
projects the obligation to the new actor without erasing ancestral
attribution. Credit flows to demonstrated interventions that overcome
independently reproduced failures and lower holdout/live recurrence.

Model/version trends require factorial trial arms (no intervention, skills,
memory, HELM) across old/new provider revisions, balanced task order, matched
held-out tasks, exact method/denominator, independent evaluator, CI/token cost
and uncertainty. Improve the machine's **decision policy and action selection**
only on demonstrated repeatable evidence, not reward hacking.

Contracts restricting privileges after a verified breach are scoped,
reversible and enforced by existing authorisation/lease doors; the agent
cannot issue, sign, or restore its own enforcement verdict. A successor must
still be able to inspect, diagnose, test and repair.

## Concrete first canary (execution, not a new control plane)

`bin/idp-karma-observe --json` reads current GitHub Actions evidence via
the existing authenticated `gh` service, bounded to one page per repository.
No new API token, database, paid model call or cloud runner is required.
It emits real run IDs, exact SHA, actor, observed GitHub timestamps, outcome
and `UNLINKED_TO_INSTRUCTION` where the GitHub event lacks a signed
instruction/QUAD link. It never invents provider/model identities or
costs. It flags duplicate/retried runs separately rather than assuming each
is waste, and distinguishes a run that has not finished from verified
success. A `--runs-json` fixture makes the same path falsifiable without API.

The declared `ai.estate.karma-observe` entry uses the **existing Chronos
Dagster scheduler**, off-Mac, to request this observation periodically.
The schedule being committed is NOT a claim that the remote Dagster clock
is running or that the Genesis founder stream consumes the result yet.
Operational acceptance is an observed cloud execution with the exact SHA,
a bounded age and a visible founder readback. Until those receipts exist,
status is `DECLARED_NOT_PROVEN_LIVE`.

## Root-cause science — inspect failed assumptions, not one bad file

Follow MAP → FILTER/REDUCE → AUTOMATE → FALSIFY → GENERALISE → measured
ENFORCEMENT. Give each pattern an inventoried denominator, bounded scope,
existing system owner and empirical improvement metric. Initial failure
families: (1) missing executable living specifications; (2) orphaned secret
custody; (3) unauthorised/missing decisions; (4) blind observability;
(5) config drift; (6) vulnerable supply chain; (7) absent operating
contracts; (8) excess privilege; (9) broken causal/provenance joins;
(10) untested failure paths. Observe negative space; do not collect
indiscriminately or freeze unrelated operations. Each successful repair
becomes estate-owned, versioned training material for subsequent generations.

Founder-grade outcome: how much each model/provider/version improved, how
much **our** intervention changed that, whether successor agents truly
correct inherited errors, what obligations remain open, and how much verified
value was created per fully observed resource bundle.
