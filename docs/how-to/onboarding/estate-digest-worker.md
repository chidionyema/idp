# Onboarding: estate-digest-worker

## What it is

`bin/estate-digest-worker` answers the founder's "update / what changed /
what's red / what's next" from a local free model. It is the on-ramp to the
estate's local ops tier (crew#929) — an always-on open-model worker that takes
recurrent operational questions off the frontier-token path.

## Why it exists

Repeatedly calling a paid frontier model to summarise the same daily estate
state is a waste of both money and latency when a small resident model can do
it. This worker proves the estate (client zero, R54) runs its own low-tier ops
work on hardware it already owns. The seven-agent roster it belongs to lives in
`docs/ops/local-ops-tier-roster.md`.

## What it needs

A host with Ollama serving `qwen2.5-coder:7b` and `kubectl` reachable. Override
with the environment variables `ESTATE_DIGEST_MODEL`, `ESTATE_OLLAMA`,
`ESTATE_STATE_FILE` (default the sibling crew `STATE.md`) and `ESTATE_CREW`.

## The contract that makes it trustworthy

The status line is computed by the worker from measured Flux and snapshot
facts and is printed by the worker, never generated by the model. The model
only writes two short narrative lines. It therefore cannot report a false
"all green" when a real red exists; and it never makes up a fact, because a
claim with no measurement behind it is refused rather than repeated.

## Running it once

```
$ bin/estate-digest-worker
STATUS: RED — flux not-Ready: alerts; chaos; crossplane;
1. WHAT CHANGED:  fix(cyrus):...
2. WHAT'S NEXT:  ...
ok estate-digest-worker answered in 145s <- qwen2.5-coder:7b (local)
```

A digest is a batch job, best scheduled on an interval, because local
generation runs at roughly one to two tokens per second on the reference i7.
It is not a sub-minute interactive reply.

## When it fails

If Ollama is down the model does not answer and the worker exits non-zero with
a clear line — it never prints a placeholder digest that looks successful.
