# The infrastructure crew

What it is, how to stop it, how to read what it did, and how to give it a ticket. Every step a
person takes is quoted from the vendor's own page.

## What it is

The infrastructure crew is a set of five agents (manager, planner, builder, verifier, watcher)
running on crewAI in one container on the estate cluster. Every 15 minutes it looks at the crew
board for the oldest open ticket labelled `lane:infra` that has no plan comment yet. It writes a
plan comment ending in an `Optimised:` line, opens a branch and a pull request on the platform
repository, and stops. It has no merge tool, no deploy tool and no cluster tool: the founder
merges and deploys. When the queue is empty it prints `idle` and exits.

Where things live:

| Thing | Place |
|---|---|
| The code and the image | the `infra-crew` repository; the image is published on every main commit |
| The cluster workload | `platform/infra-crew/cronjob.yaml` (one scheduled job, no cluster permissions) |
| Its credentials | `platform/infra-crew/external-secret.yaml` (a GitHub App token minted in-cluster, the Langfuse keys, the router key; all mounted as files) |
| The Flux row | `clusters/oke/platform.yaml`, row `infra-crew` |
| The catalogue page | Backstage, "Infrastructure crew" under the agents system (generated by `bin/catalog-platform`) |
| The drill | `drills/catalogue.yaml` row `infra-crew`, run by `bin/idp-infra-crew-drill` inside `.github/workflows/oke-check.yml` |
| The law files it reads | fetched at every start into its laws directory: AGENTS.md and AGENTS-FULL.md from the laws folder of the claude-guards repository, `crew/docs/STANDARDS.md` and `docs/reference/policy/definition-of-done.md` |

Its GitHub hand is the `infra-crew` lane of `platform/github-app/lanes.json`: read metadata,
write contents, pull requests and issues, read actions and checks. Nothing else.

## Stopping it

Three switches, each one action, each independent of the other two.

### 1. Suspend the GitHub App installation (every token dies at once)

The crew cannot read the board or open a pull request without a token, and the token is minted
from the App installation. Suspending the installation makes the next run refuse to boot.

From GitHub's page "Reviewing and modifying installed GitHub Apps":

1. "In the upper-right corner of any page, click your profile picture, then click **Settings**."
2. "Under "Integrations," click **Applications**."
3. "Click **Installed GitHub Apps**. A list of the GitHub Apps installed on your personal account will be displayed."
4. "Next to the GitHub App you want to review or modify, click **Configure**." The App is `estate-agents`.
5. "To keep the GitHub App installed for future use but temporarily block it from accessing resources owned by your account, click **Suspend**."

To bring it back: "If the GitHub App was previously suspended, you can unsuspend the app by clicking **Unsuspend**."

This switch also stops Hermes and the drill dispatcher, which mint from the same App.

### 2. The agents toggle

The one-word switch that turns every agent off at once is the `agents_enabled` toggle the board
asks for in [the agents toggle ticket](https://github.com/chidionyema/crew/issues/767). It is not
built yet. Until it lands, switches 1 and 3 are the two that exist.

### 3. Suspend the scheduled job in git

Open `platform/infra-crew/cronjob.yaml`, add `suspend: true` directly under `spec:` of the
scheduled job, open a pull request, and merge it. Flux applies the change within ten minutes and no
new run starts; a run already in flight finishes. Remove the line and merge to resume.

## Reading what it did

Every run is a trace in two places, and the drill reads the second one from outside the cluster.

- **Model traces.** Open the "Infrastructure crew" page in Backstage and click "Model traces"
  (that is Langfuse at `langfuse.<zone>`). Every worked ticket is a trace named `infra-crew.run`
  whose session is `infra-crew-<ticket number>-<run id>`; the agents, tasks, tool calls and model
  calls hang under it. The verifier's verdicts are evaluations on the same trace.
- **Logs.** On the same page click "Live logs and metrics" (SigNoz) and filter the service
  `infra-crew`. A run that refused to boot prints one line starting `REFUSED:` naming the value
  it is missing.
- **The board.** The plan comment on the ticket, and the pull request it opened from a branch
  named `infra-crew/<ticket number>`.
- **The drill.** The `infra-crew` row of the drills report: green when no queued ticket has waited
  more than an hour without a plan and every plan in the last day has a trace behind it; red
  names the ticket that is waiting or the plan with no trace.

## Giving it a ticket

The board is the `crew` repository. The label `lane:infra` has to exist there once; from GitHub's
page "Managing labels":

1. "On GitHub, navigate to the main page of the repository."
2. "Under your repository name, click **Issues** or **Pull requests**."
3. "Above the list of issues or pull requests, click **Labels**."
4. "To the right of the search field, click **New label**."
5. "Under 'Label name', type a name for your label." The name is `lane:infra`.
6. "To save the new label, click **Create label**."

Then open an issue on the board with what you want done, in plain words, and put the label on it:

1. "Navigate to the issue, pull request, or discussion."
2. "In the right sidebar, click **Labels**, then click a label." Click `lane:infra`.

Within 15 minutes the crew takes the oldest such ticket that has no plan comment. Expect a plan
comment ending in an `Optimised:` line, a pull request from a branch `infra-crew/<ticket number>`,
and a trace in Langfuse. If nothing happens within an hour the drill goes red and names the ticket.

## Not done

- The crew reads the router with the router's own key; a virtual key minted for this crew alone,
  with its own budget, replaces that line when the router's key management is on.
- The `agents_enabled` toggle (switch 2) is not built; the board ticket above tracks it.
- The `lane:infra` label does not exist on the board yet; the seeding steps above create it.
- The image `infra-crew:main` is published by the crew repository's image workflow on its first
  main commit; until then the scheduled job's pod cannot pull and Flux reports it.
