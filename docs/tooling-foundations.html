The short version

We were writing our own tools for jobs the industry already solved. That is cheap to start and expensive to defend, because a stranger has no reason to trust code only we have ever run.

So we are moving job by job onto tools with a foundation behind them. As of 24 August all four jobs are running. Three run on the tool this page originally named. The fourth does not: we said we would use the OSS Review Toolkit for licences and we used conftest instead, and the card below says what that swap cost rather than quietly claiming the tool we did not install.

Nothing here costs money. Every tool is Apache-2.0, installed with one command, running on the laptop. The commercial products that do the same jobs start at $14,400 a year and go past $59,000.

Each card is one job the platform has to do. It says what we built ourselves, what we run instead, who stands behind that, and what happens if it dies.

Knowing what is inside what we ship

Shipped 24 Aug
Where we are

Installed and running as bin/supply-chain. One scan writes a parts list in two formats and grades it: 4,996 packages, 3,081 with a declared licence, 447 vulnerabilities, 49 of them critical, nothing sell-blocking. Exit 0. The captured output is in the repo at docs/evidence/supply-chain.txt.

What we used

Syft to write the parts list, Grype to check it — exactly as named here. Both Apache-2.0, both from Anchore, both installed with one command.

Apache-2.0 Syft 9,450 stars Grype 12,777 stars
The honest bit

Syft and Grype are not CNCF projects. They appear in the CNCF's landscape directory, which lists tools that exist in the ecosystem and confers no status at all. Trivy is the same. We will say "widely adopted", never "CNCF", because the second one is checkable and false.

Knowing what we are allowed to sell

Shipped 24 Aug — but not with the tool named here
Where we are

The licence gate runs inside bin/supply-chain. Of 4,996 packages, 3,081 carry a declared licence and none of them is sell-blocking, so the gate exits 0. It refuses AGPL, SSPL, BUSL, the Elastic licence, non-commercial Creative Commons and the Commons Clause — and it also refuses a full parts list with no terms in it at all, rather than reading an empty scan as clean.

It warns rather than refuses on two things, and both are printed every run: 1,915 packages declare no licence, which is usually a metadata gap but grants us nothing if any of them ship in the product; and two packages are copyleft (axe-core MPL-2.0, rollup-plugin-dts LGPL-3.0-only), fine to use and a constraint on distribution.

What we used, and it is not what this page said we would

Syft already extracts the licence terms while it writes the parts list, so we wrote the rule in Rego and run it with conftest — policy/licences.rego. We did not adopt the OSS Review Toolkit.

CNCF (graduated) Apache-2.0 conftest · Open Policy Agent
What that substitution cost us, stated plainly

We swapped ORT for conftest because ORT needs a Java runtime and has no Homebrew formula, while conftest was already installed for the placement gate. One tool, two policies, no new runtime.

The trade-off is real and it goes on the risk register. ORT has Linux Foundation governance and is run by Bosch, Volkswagen, Porsche and Deutsche Telekom; the OPA project has CNCF governance, which is comparable, but the licence rules themselves are ours — a file only we have ever run, which is the exact thing this page was written to stop. ORT also ships a curated licence-classification database we do not have, so our list of sell-blocking terms is a list we maintain by hand and it will go stale.

What keeps that honest for now: bin/policy-test runs six fixtures through the real conftest binary and checks the exit code each time. Three of them are licence fixtures — one permissive tree that must pass, one sell-blocking tree that must fail, and one empty scan that must also fail. A rule that starts saying yes to AGPL fails that run, and so does a rule that goes quiet. It is a smaller claim than ORT's, and it is the one we can actually show.

Three things we were about to get wrong

These are corrections to claims we were on the way to making. Each one would have been caught by a buyer in an afternoon, and being caught is worse than the fact itself.

Backstage is CNCF Incubating, not Graduated

It reached Sandbox in September 2020 and Incubating in March 2022, which is still its most recent move. Four separate sources agree, including the CNCF's own landscape file. Writing "Graduated" on a diligence page would have been a false claim that takes one search to disprove.

Trivy, Syft, Grype and Kratix are not CNCF projects

We had them recorded as CNCF-backed.

All four appear in the CNCF landscape with no maturity stage attached, which means listed, not governed. They are still good tools with permissive licences. They are just not the credential we thought they were.

Conftest will fail an automated licence scan

Its licence text is plain Apache-2.0, but the file carries a custom preamble that defeats GitHub's detector, so it reports as unknown. A buyer's scanner will flag it. Better that the answer is already written down than that we improvise it in a meeting.

Check any of it yourself

Every claim above is one command away. These are the commands, so nobody has to trust the page.

Is Backstage really only Incubating, and is OPA really Graduated? 
curl -s https://raw.githubusercontent.com/cncf/landscape/master/landscape.yml \
  | grep -A12 'name: Backstage' | grep 'project:'
Are Trivy, Syft and Grype CNCF projects? 
curl -s https://raw.githubusercontent.com/cncf/landscape/master/landscape.yml \
  | grep -A12 -E 'name: (Trivy|Syft|Grype)' | grep -c 'project:'
# prints 0 — no maturity stage on any of the three
What licence does each tool actually carry? 
for r in backstage/backstage simonw/datasette open-policy-agent/opa \
         anchore/syft anchore/grype oss-review-toolkit/ort; do
  gh api "repos/$r" --jq '"\(.full_name)  \(.license.spdx_id)"'
done
Does Humanitec really ship no licence? 
gh api repos/humanitec/terraform-provider-humanitec --jq '.license'
gh api repos/humanitec/terraform-provider-humanitec/contents --jq '.[].name'
# license is null, and no LICENSE file is listed
Does the risk register policy actually run? 
jq -s '{risks: .}' risk/REGISTER.jsonl \
  | conftest test --parser json -p policy -
# 7 tests, 7 passed, 0 failures

What we still owe

  • Install Syft and Grype and put the parts list where a buyer can read it. One command each; the reason it has not happened is time, not cost.
  • Stand up the OSS Review Toolkit so the licence answer is generated rather than remembered. Needs a Java runtime first.
  • Update Backstage. We run 1.54.0. Current is 1.54.3, released two days ago. Three patch releases behind is fine; forgetting we are behind is not.
  • Write down two risks a buyer would find anyway — Datasette has one maintainer with 2,910 commits against the next person's 20, and Spotify holds four of Backstage's five maintainer seats. Both are real, neither is disqualifying, and both are far cheaper to disclose than to be caught on.

How we know. The maturity claims come from the CNCF's own landscape file, parsed directly rather than read off a vendor page. The licence and star counts come from the authenticated GitHub API on 24 August 2026. Prices come from each vendor's published pricing page on the same day.

What is weaker. The criticism of Backstage's maintenance cost is real and named — Spotify's own head of engineering for Backstage put average adoption at 10%, and an engineer at SPS Commerce described it publicly as a framework for building a portal rather than a portal. Some of those quotes were confirmed from one source only. The Gartner figures that circulate on this subject trace back to a vendor's blog citing Gartner second-hand; the note itself is paywalled and we have not read it, so we do not repeat them.
