# Proof of Yield — enforcement, SLA, and failure mapping

**Status:** enforced locally on commit and push. Server-side PR enforcement is not yet active (see gaps).

## 1. The yield equation, with gates

    U(a | S) = I_gates(a, S) * ( w_y * V_test(a) + w_f * P_urgency(a) + w_s * M_alignment(a) - w_c * C_cost(a) )

- I_gates is 0 or 1. Any hard violation zeroes the action: disk below 1500 MB, push to main, unverified
  claim treated as certified, or a commit without a valid proof.
- V_test is verified local evidence (projector 19/19, build green, integration 5/5).
- P_urgency is time pressure (incident, meeting, blocker).
- M_alignment is the founder's recorded steers.
- C_cost is tokens, wall time and risk.

The proof certifies the terms that are locally checkable. It does not certify external services.

## 2. The proof artifact

Generated by estate-proof to ~/.estate/state/PROOF_OF_YIELD.json:

| Field | Meaning |
|---|---|
| generated_at | unix seconds; gate rejects older than 24h |
| argon_head, idp_head | commit identity the proof covers |
| argon_dirty_sha256, idp_dirty_sha256 | hash of status + diff; gate rejects drift |
| disk_free_mb | must be >= 1500 |
| projector_pass / fail | must be 19 / 0 |
| build_ok | must be true |
| ok | conjunction of the above |
| receipt | HMAC-SHA256 over canonical JSON with ~/.estate/state/proof-key |

Human view: ~/.estate/state/PROOF_OF_YIELD.md.

## 3. Enforcement (verified)

Git uses core.hooksPath = ~/.estate/hooks. Wrappers there call estate-commit-gate first, then exec the
original governance hook unchanged (originals preserved as *.estate-governance).

- pre-commit: verifies the proof HMAC, status, age, and that both worktrees still match the proof.
- pre-push: regenerates the proof (runs 19 tests + build), then verifies it.

Observed:
- clean tree -> ESTATE GATE: PASS (pre-commit), exit 0
- tracked file changed after proof -> exit 1, "worktree changed since proof"
- proof deleted -> exit 1, "no proof"

No bypass variable is implemented. A failed gate prints the exact remediation: run estate-proof.

**PR enforcement:** local pre-push is enforced. GitHub branch protection requiring a proof check is not
configured; the Actions runner is currently unavailable. Until a required check exists, a human with
admin rights can still merge on the server. This is stated, not hidden.

## 5. Failure modes and where they are handled

| Failure | Detection | Handling |
|---|---|---|
| commit without proof | pre-commit gate | refused, remediation printed |
| code changed after proof | dirty-hash compare | refused, rerun proof |
| push without proof | pre-push regenerates then verifies | refused on any red |
| disk below floor | wind, proof, demo | reclaim-first; non-reclaim work stopped |
| bus down | wind, demo | process restart; debug pack 04 |
| DNS missing | wind, demo, debug pack | create CNAME; debug pack 03 |
| tunnel down | debug pack, llm health | restart connector; 03 |
| Telegram silent | wind, debug pack 05 | check otto/8099 and creds |
| router degraded | wind (ok=false, chain_break_at) | investigate before routing |
| projector regressions | test:projector + build | block push |
| DB corruption | debug pack 06 integrity | restore from checkpoint |

Every row maps to a command a future session can run without rediscovering the estate.

## 6. Wind protocol

estate-wind prints WIND: OK | WARN | CRITICAL with per-signal detail and an action.

- OK: proceed.
- WARN: proceed, but do not claim yield until warnings are addressed.
- CRITICAL: stop non-reclaim work, run estate-debug-pack, fix red first.

## 7. Enterprise gaps (named, not hidden)

1. No durable time-series store for SLO history; wind is point-in-time.
2. No paging/on-call integration.
3. No server-side required check for PRs yet (runner unavailable).
4. No formal TLA+ proof that the implementation refines the spec; the predicates are tests.
5. No disaster-recovery drill for estate.db or the vault.
6. Estate-yield candidate is at Authority U; it is not promoted and replaces nothing.

Closing these is the next engineering tranche, not a documentation task.
