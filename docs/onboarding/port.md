# Onboarding: port-gate

## What it is

`bin/port-gate` is a stand-alone script name (stem `port`) for the gate that
enforces the ports rule: `python3 bin/port-gate` checks every compose
publication in this repository against `catalog/ports.yaml`; `python3
bin/port-gate --live` additionally checks every real listener on this machine
right now, read with `lsof` at the moment it runs. Full detail on the rule
that governs what it checks — the two-file split between intent and
measurement, how to claim a port, the GitHub ruleset side of the same page —
is in `docs/onboarding/ports.md`; this page is the gate command itself.

## Why it exists

Founder ruling R20: only the gateway binds a non-loopback address. R22 needs a
mechanical check, not a reviewer's memory, because a port bound at 2am to get
a UI up is how Dagster ended up on 3210 undeclared on 2026-08-24. `--live` was
made to read the machine directly rather than a periodically-refreshed
inventory snapshot after a 73-minute-old snapshot once failed a service that
had already fixed itself — a guard refusing correct work is an outage (LAW
38), and a stale reading cannot be trusted to say "clean" either.

## When it runs

`bin/idp-ci` runs the static (non-`--live`) form on every PR, proved against
`tests/fixtures/ports-bad/`. `bin/idp-verify` runs `--live` after the stack is
up, since only a running machine has real listeners to check.
