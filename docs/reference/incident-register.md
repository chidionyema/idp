# Incident register

Every incident the estate has suffered, one row each, generated by `bin/incident-register` from the
docstring of every `tests/test_incident_*.py` (crew#679; founder 2026-08-30: "take incident as input,
use it to generate chaos experiments/drills"). The file is
[`incident-register.yaml`](incident-register.yaml); `bin/incident-register --check` runs in the fast
gate and refuses a new incident test that has no committed row.

Each row carries a `fault_class`. Rows marked `injectable: true` (pod-crash, rollout-stall, network,
secret-rotation, capacity, clock, scheduler) are the input to the chaos generator (crew#679 CP3);
`ci-pipeline` and `process` rows are closed by gates and cannot be recreated in a cluster;
`unclassified` rows are listed by name so nobody mistakes an unread incident for a covered one.
