# Gate: reversibility

*`mutation-reversibility` · ADR 0024 (Otto runs every tool and asks only for the unundoable), ADR 0025 (agents hold no write on production), LAW 38 (a guard that refuses correct work is an outage) · planes: ci, session*

A mutation that carries no inverse is a mutation nobody can take back: every envelope the estate admits names either a deterministic inverse with a state probe, or an irreversible exemption whose attestation is a real signature over the envelope subject -- never a token that merely looks like one. A gate that cannot read its schema or its verifier is BLIND (exit 2), because a machine that cannot judge has not found a defect (LAW 38).

## The registry's own lines

- when it passes: an envelope with no inverse, an inverse that echoes the forward, or a forged exemption token is refused; a deterministic inverse and a genuinely signed exemption pass; the gate exits 2 (BLIND) when it cannot read its schema or verifier
- when it refuses: an admitted mutation carries no verifiable inverse, or the gate refuses correct work because it could not read its own inputs (LAW 38)

Origin: The estate had three things that look like reversibility and none of them is it: bin/idp-rollback-only-diff gates a diff that is ALREADY a rollback; rewind is a destructive capability an agent may invoke rather than an obligation attached to a forward mutation; ADR 0024 routes the un-undoable to a human but never demanded the artefact exist. This gate closes that gap as a field on the envelope the ledger door (docs/specs/2026-09-15-typed-multidomain-mutation-ledger-door.md) already consumes -- not as a second envelope beside it (LAW 43). The rejected first draft accepted a human quorum token by startswith("sig-live-quorum-"), which a forged string passes; the exemption path here runs sovereign.verifier.verify_attestation (ed25519 over the subject), the same check admission runs, and the fixture that carries the magic-prefix shape is refused by that signature check rather than by luck.
