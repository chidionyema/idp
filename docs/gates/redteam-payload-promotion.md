# Gate: redteam-promoter

*`redteam-payload-promotion` · the missing wire of the adversarial loop -- red_team_payloads generates attacks and the proxy blocks known signatures, but nothing taught the proxy what red team had already proved defeating, so a hole stayed open until the same lesson arrived as an incident. LAW 38 (a signature derived from pure noise refuses correct work), LAW 43 (one writer of via_negativa:banned_signatures -- the promoter calls the RCA worker's own _persist, never a second mechanism) · planes: ci*

A red-team payload that defeated the proxy must become a signature the proxy blocks: the promoter derives a signature from the payload and writes it through the RCA worker's one _persist, closing the loop from the eval plane to the live prompt path. A payload whose content is all dynamic values derives NOTHING -- promoting it would ban a bare UUID and refuse correct work (LAW 38) -- and an unreadable payload is BLIND (exit 2), never a promotion.

## The registry's own lines

- when it passes: a defeating payload derives a signature the proxy blocks; a dynamic-only payload derives nothing and is refused; the graded tree is clean and the derivation is checked against the proxy's own source
- when it refuses: a payload that defeated the proxy cannot be promoted, or the promoter derives a signature from pure noise and would refuse correct work

Origin: The estate had every part of an adversarial loop and no wire between them: platform/eval/red_team_payloads.py generates and classifies payloads, platform/eval/red_team_loop.py scans transcripts for fired payloads, bin/negative-constraints-proxy blocks a tool call whose normalized name or arguments match via_negativa:banned_signatures, and bin/rca_worker/worker.py writes that set -- but only from real production failures. Nothing promoted a synthetic payload the red team proved defeating. This is the wire. It is deliberately not an inference micro-model on the hot path: a defeating payload becomes a signature the proxy rejects at set-membership cost, so the loop is self-improving with no added latency on every prompt. The derivation is checked against the proxy's OWN Go source (builtinSignatures, normalize, match) in tests/test_redteam_promoter.py, so the two cannot drift.
