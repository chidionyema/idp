# Gate: admitted-mutation

*`admitted-mutation-reversible` · ADR 0025 (the Greenlane grows a row at a time, and a row is admitted only when its scope binary exists with a refused and a passed fixture), ADR 0024 (every mutation carries its inverse), LAW 43 (the reversibility judgement is bin/idp-reversibility-gate, called, never re-decided) · planes: ci*

A pull request may auto-merge through the Greenlane as a reversible mutation only when the executor ADMITTED that ledger, the admitted envelope carries a verifiable inverse (bin/idp-reversibility-gate grades it), and the branch touches nothing the admitted bundle never named. The branch must be `mutation/<ledger_id>` -- the executor's own naming. Anything else waits for the founder like any other platform change.

## The registry's own lines

- when it passes: an admitted reversible mutation on a mutation/<ledger_id> branch passes; a non-mutation branch or an admitted envelope without an inverse is refused; an unreadable ledger is BLIND and never a pass
- when it refuses: a pull request that is not an admitted reversible mutation is treated as landable, or a real one is refused

Origin: ADR 0025 gave the Greenlane exactly one row (the image-tag bump, proved by bin/idp-image-only-diff) and fixed how it grows: a row is admitted when its scope binary exists, proved both ways. This is the estate's first non-tag row: a mutation the executor proposed, verified, sealed and admitted -- a change carrying its own inverse and a Deterministic Verifier signature over the exact bundle bytes. The binary reads the executor's own ledger (only verify_mutation -> seal_mutation -> admit_mutation can write it) rather than trusting a branch name or a label, so a PR that lacks any of the four facts waits for the founder. Built as a row in the ONE existing mechanism, never a second merge path (the stitching ADR 0025 forbids).
