# Gate: contract

*`contract` · founder essay 2026-09-14, the Reasoning Gateway ("Design-by-Contract for Tool Calls... A deterministic script (NOT the agent) checks the post-condition against the live system. If it fails, the PRM penalises the trajectory and the agent is forced to adapt before continuing") · planes: ci*

Every tool call declares a pre-condition and a post-condition in plain English (`<subject> <op> <value>`, or `<subject> passes`/`fails`, with an optional `within <N>s` deadline); a deterministic script -- never the agent -- checks the post-condition against declared observations after the tool runs, and refuses the next step the instant the post-condition still fails at its deadline

## The registry's own lines

- when it passes: a tool's pre-condition holds before it is credited as run, and its post-condition holds by its own deadline
- when it refuses: a post-condition probe never passed by its deadline and the run was credited as complete anyway -- the "I assume the database is up" case the founder's essay names. Deterministic: a small condition grammar over declared observations, no frontier LLM judge (per the ticket's own stated risk); a subject with no observation at all is BLIND, never assumed to hold; no second live prober is wired here (R43) -- this grades observations a caller declares, real or replayed from a live probe upstream.
