# Gate: aevum-evidence

*`aevum-evidence` · decision 0028 · planes: ci*

A receipt that does not verify is not evidence: every recorded agent action chains to the previous one and is covered by a signature, and an EMPTY ledger is a fail-closed FAIL rather than a clean bill -- Aevum's default store is in-memory and verify_sigchain() answers True about a chain with no events, so a misconfigured deployment reports green while recording nothing

## The registry's own lines

- when it passes: a receipt chains to its predecessor and is covered by its signature; an altered record and an empty ledger are both refused
- when it refuses: an altered record or an empty ledger passes as evidence

Origin: Founder, 2026-09-12: "get Aevum wired for all current and future repos." POPDD signs with HMAC, a symmetric key, so only the holder of the signing key can verify a receipt; decision 0028 records the measured comparison and adopts Aevum (Ed25519 + ML-DSA-65, COSE_Sign1, RFC 3161, standalone aevum-verify). The whole value is one property -- an altered record must fail verification -- so the gate is proved both ways and fails closed on an empty ledger, the way bin/idp-calico-deny-log fails closed on an empty deny feed.
