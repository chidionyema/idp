## Root cause, stated once

The estate built **consumers** (a CI gate, a token door, a page) and not the **producers half**
that makes them reachable and verifiable: a DNS binding, a verifier, a public-key route. Every
check along the way graded the code and the page's existence, never "can the founder actually
approve" or "can the lane actually mint". Same class as the YIELD score: proof of shape, not of
operation.

## Peer instructions

1. **One verifier, one key route.** Do not add a second passkey tool. The follow-up is
   `bin/idp-passkey-verify` (challenge → URL → poll → verify against `reg:current` → seal) plus
   `GET /public-key` in the worker. Both paths are outside `.github/workflows/`, so they land
   without a passkey seal.
2. **Do not touch the token action or `greenlane.yml`.** #8182 owns that change; a second edit
   will re-open the passkey gate and re-block the lander.
3. **Queue path first.** When a lane must land and the PR judge 401s, the queue check_run path
   mints; a stamped commit pushed to `queue/<batch>` is the route.
4. **DNS owners:** the Cloudflare custom domain for `passkey`, the three tunnel CNAMEs
   (`estate-bus`, `otto`, `llm`) and the apex A-record deletion are founder/Cloudflare-console
   actions. No agent has the account token locally.
