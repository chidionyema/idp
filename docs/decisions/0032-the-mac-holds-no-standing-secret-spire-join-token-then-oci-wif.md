# 0032. The Mac holds no standing secret: SPIRE join_token, then OCI WIF over a public OIDC issuer

2026-09-21. Status: accepted. Supersedes nothing; extends the identity row of
`docs/reference/security-policy.md` (A.5.16, A.8.24) and the zero-trust row of
`docs/decisions/0029-definition-of-done-v3-is-five-checks-none-self-graded.md`.

## The instruction

Founder, 2026-09-21: deliver the zero-trust ("elite 2100") identity on the free tier for a
macOS endpoint, and kill the clunky browser-login / human secret-delivery bootstrap. "Do the
standards research first, properly." No half-measures — this is a commercial product, and the
choice must be defensible from primary sources, not from memory.

## The evidence this was needed

The estate's own scorecard against NIST SP 800-207 + SPIFFE/SPIRE + Microsoft Entra Agent ID +
OCI WIF scored **1 of 5**. Four rows pass on paper; the device row fails, and the root is a
standing secret:

- `~/.local/state/idp/agent-key` — one bearer key, on disk, that never expires by itself.
- `platform/jit/broker/broker.py:470` — `hmac.compare_digest(presented, agent_key)`: every agent
  presents the same shared key. `broker.py:458` says the quiet part: *"One key covers every
  agent... Per-agent keys are WJ.13's problem."*
- No federation endpoint accepts a laptop: `platform/oci/vault.tf` is instance principal
  (in-cluster), `platform/oci/crossplane.tf` is a workload principal scoped to `cluster_id` for
  the `crossplane-system` service account, and `platform/oci/provers.tf:8` records that both the
  laptop and a pod were refused.

The only door that currently opens from the Mac (`bin/idp-oci-session`) *is* a browser login; the
only delivery path (`bin/idp-mac-secret-deliver`) is gated behind a cloud identity the Mac does
not have. The circle closes on itself: no cluster access without a key, no key without cluster
identity.

## What the standard actually says (verified from primary sources, 2026-09-21)

- **NIST SP 800-207** — subject *and device* are authenticated separately; authentication is
  asserted per session, not at a perimeter.
- **SPIFFE Concepts** — a workload *need not co-deploy authentication secrets*; keys are
  short-lived and auto-rotated.
- **Microsoft Entra Agent ID** — *"It doesn't have credentials on its own"*; it authenticates
  through a federated identity credential held by a blueprint, not by the agent.
- **OCI Workload Identity Federation** — `docs.oracle.com/.../json_web_token_exchange.htm` and
  `.../token_exchange_grant_type_workload_id-federation.htm`. An Identity Propagation Trust
  takes a free-form `issuer`, and a JWKS source (`publicKeyEndpoint` *or* an inline
  `publicCertificate`); the doc states `/IdentityPropagationTrust` is *"cloud-agnostic and
  supports integrations with any cloud provider."* There is no issuer allow-list and no
  dependency on the OKE OIDC endpoint or on an Enhanced cluster.
- **SPIRE macOS node attestation** — `doc/plugin_server_nodeattestor_jointoken.md`: a
  one-time-use pre-shared token, generated by `spire-server token generate`, yielding
  `spiffe://<trust_domain>/spire/agent/join_token/<token>`. The agent builds for macOS
  ("Quickstart for Linux and MacOS X"); the `unix` WorkloadAttestor supplies `unix:uid`/`unix:gid`
  selectors to bind a user's processes to an SVID.

## The decision

**1. The Mac bootstraps with a SPIRE `join_token`, once.** The token is generated on the server,
consumed at attestation, and is one-time-use. After attestation the agent holds its own key
(`KeyManager` disk or memory) and obtains short-lived SVIDs from the Workload API. **No standing
secret remains on disk after bootstrap.** The one-time provisioning event is the friction we
accept; it is not a standing credential. Rejected alternatives, each of which *shifts* a standing
secret rather than removing one: `x509pop`/`sshpop` (an existing long-lived cert/key), and the
Secure Enclave (no maintained SPIRE node attestor for macOS).

**2. OCI federation rides a public SPIFFE OIDC issuer, not an Enhanced cluster.** Enable
`spiffe-oidc-discovery-provider` (currently `platform/spire/values.yaml:90` `enabled: false`);
give it a trust bundle, an `issuer`, and a public Ingress with a Let's Encrypt (`cert-manager`)
certificate. Register **one** Identity Propagation Trust whose `issuer` is that Ingress URL and
whose `publicKeyEndpoint` is the provider's JWKS. The Mac then presents a JWT-SVID as
`subject_token` and receives a short-lived OCI token — no OCI key on the Mac. This is the
free-tier bypass: WIF lives in an OCI Identity Domain, which is available on any tenancy; the
Enhanced-cluster requirement belongs to the *OKE workload-identity add-on*, a different feature
that was mistakenly conflated with WIF.

**3. What is displaced, not eliminated.** The token exchange is authenticated by an OCI IAM
identity-domain OAuth client (`client_id:client_secret`), which is itself a standing secret. It
does **not** live on the Mac: it lives in the cluster, where an OCI Instance Principal signed
request can replace it outright (OKE Basic still grants the instance principal). The estate's
rule is "no static credential *on the endpoint*," and this satisfies it; we state the residual
plainly rather than pretending WIF removes it.

**4. The broker's shared key is the next layer, and it is named, not silently fixed.**
`broker.py`'s single `agent_key` remains until per-agent keys land (WJ.13). This ADR removes the
*Mac's* standing secret; it does not claim the broker is per-identity yet. That is a separate,
already-tracked change and this record exists partly so the claim is not overstated.

## Consequences

- A new public endpoint exists (the SPIFFE OIDC discovery/JWKS Ingress). It is public by design
  and is a discovery surface, not a secret; it must be TLS-terminated with a valid chain and the
  JWKS must be current, or OCI token exchange fails closed.
- `platform/spire/values.yaml` is currently k3d-shaped (`replicaCount: 1`, three-node reasoning
  in comments). Enabling the OIDC provider and pointing it at real OKE is a values + Ingress
  change, not a new system.
- No new layer is introduced: SPIRE already exists (`clusters/oke/platform.yaml:834`), the JIT
  broker already exists, the OIDC provider is the chart's own component.

## The first step built (2026-09-21): the broker's enrollment door

Item 4 above names the shared key as the next layer but leaves it unfixed. The first change toward
it is built and is deliberately *not* SPIRE — it is the broker minting per-device keys, which is
what makes item 4 false in practice for any machine that can reach the broker:

- **`Broker.enroll()` + `issue_nonce()`** in `platform/jit/broker/broker.py`. A device holding no
  broker key fetches a single-use, two-minute nonce and the public half of an ephemeral X25519 key
  (`GET /enroll/nonce`), and posts back an HMAC-SHA256 tag over the nonce keyed by an agreement
  between its estate age secret and that ephemeral key (`POST /enroll`). The broker regenerates the
  agreement with the ephemeral secret it kept and compares tags with `hmac.compare_digest`.
- **The proof is X25519 agreement, not a signature.** This is a correction to an earlier draft that
  assumed an Ed25519 signature. The estate's age identity is *native age*, not `ssh-ed25519`: the
  recipient `age1rgufr0lc4y02wfw5xjwugxpf8hmrzm3sww3nlk4uk8dmph3h7dsqqvrd0j` decodes to exactly
  `X25519PrivateKey.from_private_bytes(<the AGE-SECRET-KEY-1 scalar>).public_key()`, verified this
  turn. A native age key has no signing half, so X25519 is the only correct primitive. It is
  dependency-light (`cryptography`, already trusted for TLS) and needs no PyNaCl.
- **The shared key is not removed, it is displaced per device.** `authenticate()` now accepts an
  enrolled device's own key first and the shared `JIT_AGENT_KEY` only as a fallback, and the
  `identity` ledger line records which device by fingerprint (`device=`) instead of "an agent". The
  shared key remains for machines that have not enrolled; removing it outright is still WJ.13.
- **The age secret, not a vendor secret, is the one hand.** `bin/idp-jit enroll` reads
  `SOPS_AGE_KEY_FILE`, decodes the `AGE-SECRET-KEY-1...` scalar, performs the agreement, and writes
  the minted key to `~/.local/state/idp/agent-key` (mode 600). `bin/idp-workstation-bootstrap`'s
  `phase3_agent_identity` now calls this instead of BLINDing. Nothing is fetched from the vault and
  no browser opens; the credential the machine already restores at Level 1 is the whole proof.
- **The public route and the deployment carry it.** `platform/jit/public-door.yaml` routes
  `/jit/enroll` (POST) and `/jit/enroll/nonce` (GET); `platform/jit/deployment.yaml` sets
  `JIT_AGE_RECIPIENT` from `ESTATE_AGE_RECIPIENT` in `clusters/oke/estate-config.yaml` (a public
  recipient, so config and not a vault secret). A broker with no recipient refuses enrollment,
  which is the fail-closed default.
- **Graded both ways.** `tests/test_the_jit_broker_cannot_be_talked_into_standing_access.py` drives
  the real door: a fresh device enrolls and its key is accepted; the ledger holds the fingerprint
  and no key/nonce/MAC; a replayed nonce, a wrong MAC, and an impostor holding its own key are all
  refused (401); enrollment is closed with no recipient; and `bin/idp-jit enroll` is driven over a
  real socket. The route test asserts the public route carries exactly `AGENT_DOORS + OPEN_DOORS`.

**Relationship to SPIRE (items 1–3).** This does not replace the SPIRE `join_token` path; it is
what closes the laptop seam *today*, on the free tier, with the age identity the estate already
has. SPIRE remains the end-state for SVIDs and the OCI WIF exchange. Item 4 — the broker's shared
key — is now false for enrolled devices and true only for those still presenting the shared key.

## Proof required before this is "done"

Per `0029`, none of the above may be declared operating by the author of the change:

1. `spire-agent healthcheck` green on the Mac against the estate server (real output, not a
   render).
2. A JWT-SVID fetched on the Mac and exchanged at `/oauth2/v1/token` for an OCI token, proven by
   a real API call answered by OCI — not by a 200 from our own process.
3. The `agent-key` file absent from `~/.local/state/idp/` after bootstrap, and the broker
   unreachable from the Mac without an SVID.
4. A production log line from the exchange, cited in the closing receipt.

For the enrollment door specifically, "operating" is **not** claimed here. It is built and graded
locally; the proof line is a real `/jit/enroll` 200 from the public broker on the founder's Mac,
followed by `bin/idp-jit identity` answering with a token the cluster minted. Until that line
exists, the enrollment door is **built, not operating**, the same as (1)–(4) above.
