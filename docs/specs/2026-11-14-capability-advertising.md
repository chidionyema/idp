# Capability advertising and source authority

Publish the current action where agents pick their next step. A live advertisement names the outcome, the accountable owner, where it runs, the prerequisite or authorization, the first runnable step, proof of success, and a fallback. Put the action and its conditions together so a clipped excerpt cannot turn a conditional instruction into permission.

Retirement removes the action from normal discovery. Keep the historical source inspectable with a first-line marker and a link to current authority. The existing context compiler emits a reference without its excerpt even if retrieval ranks it first or selects a symbol beyond the warning. Keep the engine order for current files. The marker does not change authorization.

Prove the first case with an old cluster runbook taking the first rank in the current compiler. Assert its historical text stays out, the replacement source remains in engine order, and retirement is visible in the receipt. Count recurrence under the existing KARMA failure-class discipline. Reports themselves cannot settle the obligation.

## Observed failure classes

| Failure | Evidence | Correction and replay |
| --- | --- | --- |
| A high-ranked old command survives a warning placed above the matched excerpt | A regression fixture returned retired cluster instructions before the compiler fix | Rank the historic source first and select a symbol below its header. Require the compiler to drop the excerpt and surface current authority. |
| Startup and catalog entries outlive the deployment | The capability index and service labels still advertised a retired backend after the estate changed deployment targets | Check startup, discovery, portal shortcuts, and the old direct commands together. Require refused calls and preserved public health probes. |
| Declared infrastructure is mistaken for a running dependency | The replacement was approved while the live inventory recorded no running ARM host in the configured estate compartment | Require current inventory and real caller evidence before advertising the replacement as operational. |
| The same failed action is retried under a different name | Greenlane's incident record documents repeat admissions under an unchanged trusted policy | Preserve the failed predicate and evidence under the existing incident owner. Replay after an action, dependency, or authority changes. [Incident #7800](https://github.com/chidionyema/idp/issues/7800) |

For a cross-harness replay, give each harness the same task and misleading historical match. Record which source it opened first, which action it selected, and whether current authorization admitted it. Measure wrong-action selections over total trials on held-out tasks before claiming that the law changed agent behavior.
